## 1. 问题口径与信息结构

问题二的结算规则（与口径 D 完全一致，见 `q2.py`）：

- 每天 0:00 制定当天计划购电量，**计划电量 take-or-pay**（买多了不退钱）；
- 实际揭晓后储能可再调度，若供给仍不足，缺口按交易时刻电价的 **5 倍**紧急购电；
- 储能按日循环运行：`E(0:00) = E(24:00) = 6000 kWh`（各日独立，跨日连续自动满足）。

口径 E 的信息结构比口径 D 更严格：

| 口径 | 0:00 可用信息 |
| --- | --- |
| B（典型日） | 附件 1 典型日（全年逐点平均） |
| D（官方 result2） | 附件 3 的 0:00 光伏预报 + 已知负荷 |
| **E（本文）** | **历史实际（附件 2）+ 附件 1 典型日，无任何预报** |

**无前视约定**：目标日 D 的权重只依赖日历日 `≤ D-1` 的数据；预测式中出现的 `L(D-7)、P(D-1)` 等对 D 来说均已是历史。

- 标定数据起点 `START = 14`：负荷 `D-14` 滞后最早可用。

## 4. 预测模型

对目标日 D 的每个时段 t：

```
L̂(D,t) = w1 · L(D-7,t)  + w2 · L(D-14,t) + w3 · L̄(t)
P̂(D,t) = u1 · P(D-1,t)  + u2 · P(D-2,t)  + u3 · P̄(t)
```

组合后裁剪非负并转换为 kWh/槽（÷6）。权重设计要点：

1. **每天一组、144 槽共用**。逐槽独立权重在单日标定下不可识别（第 t 槽只有 1 个观测却要定 3 个权重），必然过拟合，故不采用；"每个时间点加权"由同一组权重在每个槽上作用实现。
2. **滞后选择依据**（见 `C题_经验总结.md` §1.7、§1.4）：
   - 负荷周周期极强：周内低谷在周五/周六（−37%），扣除日内形状后 `lag1008` ACF ≈ 0.955 → 用同星期几 `D-7 / D-14`；
   - 光伏无周内周期、短期持续性强（日内 lag1–4 = 0.79/0.60/0.40/0.21）→ 用 `D-1 / D-2` + 气候平均；
   - 两族都保留"典型日"分量，权重可自动在"近邻 vs 气候平均"之间取舍。
3. **softmax 参数化**保证权重恒为凸权重（非负、和=1），优化时无需投影；`θ` 无界、可逼近单纯形角点。

## 5. 单日实际费用模型

`day_cost(D, w, u)`（`models/adaptive.py:207`）由两次 LP 构成。

### 5.1 计划 LP（0:00，按预测执行；`core/lp.py:109`，门面 `q2.plan_day`）

```
min  Σ_t p_t·x_t + ε·Σ_t (c_t + d_t)
s.t. P̂_t/6 + x_t + d_t = L̂_t/6 + c_t + s_t        （功率平衡，s_t 为弃光）
     E_t = E_{t-1} + η·c_t − d_t/η                 （储能动态，E_0 = 6000）
     E_144 = E_0 = 6000                            （日循环）
     x_t ≥ 0,  0 ≤ c_t, d_t ≤ 833.33,  0 ≤ s_t ≤ P̂_t/6
     1200 ≤ E_t ≤ 10800
```

### 5.2 执行 LP（实际揭晓后；`core/lp.py:188`，门面 `q2.exec_day`）

计划购电量 `x` 已承诺不可改；储能按实际负荷/光伏再调度，缺口用紧急购电补齐：

```
min  ε·Σ_t (c_t + d_t) + 5·Σ_t p_t·e_t
s.t. P_t/6 + x_t + d_t + e_t = L_t/6 + c_t + s_t
     （储能动态与边界同计划 LP；s_t ≥ 0）
```

### 5.3 计费

```
C_D(w,u) = Σ_t p_t·x_t + 5·Σ_t p_t·e_t            （元）
```

说明：

- **ε = 1e-3 元/kWh** 是极小正则项，用于在等价位段内唯一化购电/充放方案，消除 LP 多解导致的费用函数跳变（对日费用的影响 <0.1%；口径 D 默认 ε=0，行为不变）；
- take-or-pay 的权衡（多买 vs 紧急）完全由 5 倍罚与两种费用的相对大小在标定中自动决定，无需人为设"保守系数"。

## 6. 标定问题

目标日 D 的权重由**刚完成的窗口**上的实际总费用决定：

```
J_D(θ) = (1/|S|) · Σ_{k∈S} C_k( softmax(θ[0:3]), softmax(θ[3:6]) )      S = {k : max(14, D-W) ≤ k ≤ D-1}
θ*_D  = argmin_{θ∈R⁶} J_D(θ)
```

部署：`(w,u) = softmax(θ*_D)` 用于第 D 天的计划。`W=1` 即"当天结束 → 在当天实际费用上标定 → 预测次日"，与题述一致；`W∈{3,7,14,30}` 用于敏感性分析。

注意：`J_D` 是两次 LP 最优值的复合函数，**没有凸性保证**，求解方法必须专门设计（见 §7）。

## 7. 求解算法：网格全局定位 + 数值梯度精化

### 7.1 难点与纯局部方法的失效

`C_k(w,u)` 对权重的依赖链是：`w → 预测 → 计划 LP 的右端项 → x* → 执行 LP 的右端项 → 费用`。LP 最优值对右端项是凸分段线性（PWL）的，链式复合后对权重仍是**分段线性、非光滑**；再加上 §5.3 的 LP 多解/基切换，费用面存在窄尖峰与跳变。

开发期抽样诊断（临时脚本，未纳入 `RESULTS_REPORT`；目标窗口为日历日 30）：

| 方法 | 费用/元 | 相对全局最优 |
| --- | --- | --- |
| 步长 0.1 网格（4356 组）全局最优 | 22 840 | — |
| 等权出发 Adam（10 步） | 23 895 | +4.6% |
| Nelder–Mead（400 迭代） | 23 333 | +2.2% |
| 逐日热启动链 | — | gap 在 −0.9% ~ +5.8% 间波动 |

结论：单一局部方法不可靠，必须"**先全局粗搜，再局部精化，且精化只在改善时采纳**"。

### 7.2 网格全局定位

- 单纯形网格步长 `grid_step = 0.2`：`n = 5`，权重取 `(i/5, j/5, (5−i−j)/5)`，单变量 21 组，联合 **21×21 = 441 组/天**；
- 对每个日历日 `k = 14..364` 计算整行成本表 `C[k,i,j] = C_k(w_i, u_j)`（351 天 × 441 组 ≈ 15.5 万次 day_cost）；
- 每次 day_cost = 1 次计划 LP + 1 次执行 LP（各 720 变量、289 条等式约束 + 边界），单次约 12 ms；
- 选权重：目标日 D 取窗口 `[max(14,D-W), D-1]` 内网格行均值的 argmin（`weights`，`q2_adaptive.py:267`）。

### 7.3 数值梯度精化（`calibrate`，`:182`）

以网格最优为初值，用 `torch.optim.Adam` 做少量步的局部精化：

- 初值：`θ0 = (ln w*, ln u*)`（softmax 后即网格最优权重）；
- 梯度：`θ` 空间**中心差分**，步长 `eps = 0.1`，6 维 → 每步 12 次 day_cost 评估；
- 更新：Adam，`lr = 0.05`，10 步（共 120 次评估）；softmax 自动保持单纯形；
- **接受回退**：精化后费用必须严格小于网格最优才采用，否则回退 `θ0`（防非光滑变差）；
- 标定日与使用日：`TH[k]` 在日历日 k 上标定、用于目标日 `k+1`，严格无前视（`_one_day`，`:204`）。

精化收益（`imp = max(0, C_grid − C_pol)`）：**334 天中 269 天改善，日均 87.2 元，全年 22 986 元**。

### 7.4 并行与缓存

- 按天并行：`multiprocessing.Pool`，模型经 initializer 注入子进程（Windows spawn；入口由 `if __name__ == "__main__"` 保护），默认 `min(8, CPU核数)`；
- 缓存：`code/outputs/cache/q2e/table_<md5>.npz`，键 = 5 个数据数组 + `(grid_step, steps, lr, eps_grad)` 的 md5，任一变化才失效；
- 缓存内容：`C (365,21,21)`、`TH (365,6)`、`imp (365,)`；首次建表 **476 s**，命中后秒载。

### 7.5 伪代码

```text
# 建表（并行，逐日独立；k = 14..364）
for k in 14..364:
    for (i, j) in 21×21 simplex grid:
        C[k,i,j] ← day_cost(k, w_i, u_j)          # 计划(按预测) + 执行(按实际) + 紧急购电
    θ0 ← log(网格最优 (w*, u*))
    θk ← Adam(J_{k+1}(θ), θ0; steps=10, lr=0.05)  # 标定在日 k，供次日 k+1 使用
    (TH[k], imp[k]) ← (θk, C_grid − C_Adam) 若 C_Adam < C_grid，否则 (θ0, 0)

# 全年滚动模拟（D = 31..364）
for D in 31..364:
    (w, u) ← softmax(TH[D−1])                     # W=1 主结果（W>1 时改为窗口查表）
    x ← plan_LP( forecast(w,u,D) )                # take-or-pay
    cost_D ← p·x + 5·p·e( exec_LP(actual_D) )     # 执行 + 紧急购电
total ← Σ cost_D
```

### 9.3 结论

1. **W=1 存在过拟合**：单日回看使权重逐日跳动，W≥3 后迅速收敛（1398~1402 万元）；
2. 自适应加权把"典型日"基线从 2311.5 万元降到 ~1400 万元，**验证了历史加权的价值**；
3. 纯历史方法仍比附件 3 预报（口径 D）高约 1%（W=7 时 +0.94%），说明给定预报质量较高，但 E 完全不需要预报数据，可作为预报缺失时的替代方案；
4. 相对事后最优下界仍有 7.2% 空间，主要来自"用昨天的数据拟合明天"这一信息缺口；
5. 梯度精化在纯网格基础上再省 2.0 万元/年（1420.9 → 1418.9）。

## 10. 复杂度、局限与改进方向

**复杂度**：351 天 ×（441 网格 + 120 精化）≈ 19.7 万次 day_cost；8 进程建表 476 s，缓存后单口径模拟 5~7 s。

**局限**：

- 属于 follow-the-leader 式在线标定，不是理论保证的在线梯度下降（无 regret 界）；
- 权重优化不保证全局最优（网格 + 局部精化的近似）；
- W=1 主结果过拟合，实用值应取 W≥3；
- 未利用附件 3 的预报信息。

**可改进方向**：

1. W>1 的池化窗口目标也做梯度精化（当前仅查表）；
2. 把附件 3 的 0:00 预报加成第 4 个源（大概率超过口径 D）；
3. 引入保守裕度 `κ_L·L̂`、`δ_P·P̂`（5 倍罚下通常进一步省费用）；
4. 权重做 EWMA 平滑，或目标改为 `mean + λ·CVaR` 的风险厌恶版本。
