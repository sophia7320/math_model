# 执行器"段末硬目标"机制对照实验（小样本）

> 日期：2026-09-13  
> 数据：附件 2/3 实测（小样本，不做全年大仿真）  
> 引擎：统一结构（2 日滚动 + EWMA h=5 预测 + κ/m + 40 情景联合残差对冲）  
> 复现：`uv run python -m solve.exec_policy_probe`（输出 `code/outputs/exec_policy_probe.csv`）

## 1. 问题定位

原逐槽因果执行器（`q2.exec_segment_causal`）要求 SOC 在每个决策段的末端
（6:00/12:00/18:00/24:00）跟踪规划轨迹（"可达性投影"）。实测该机制会：

- 在段末为达成高目标而**被迫充电**（电量不够高时），充电负荷叠加缺口 →
  **紧急购电（5 倍价）充能**；
- 在目标偏低时**扣留放电**，让本可由储能覆盖的缺口走紧急购电。

另一并行分析（基于旧引擎 result3.xlsx 的逐槽分解）显示：紧急购电的
四个小时尖峰（5:00 / 11:00 / 17:00 / 23:00）合计约占全年紧急量的 69%，
即该机制的产物。

## 2. 实验设计

在统一结构下，用两个小样本对比三种执行策略（计划层完全相同，仅执行层不同）：

| 策略 | 含义 |
|---|---|
| `target` | 段末目标硬跟踪（旧口径） |
| `dayend` | 仅当日最后一段跟踪日末目标，中间段自由 |
| `free` | 无任何段末目标，仅受容量/功率约束（现行统一口径） |

样本：夏季应力（2025-06-01 ~ 07-30，60 天）、秋季应力（2025-10-16 ~ 12-01，47 天）。

## 3. 结果

### 夏季样本（60 天）

| 策略 | 总费用/万元 | 计划 | 偏差 | 紧急 | 弃电/kWh | 窗口紧急 0-6/6-12/12-18/18-24（万元） |
|---|---|---|---|---|---|---|
| target | 329.4 | 250.0 | 9.8 | **57.3** | 415 391 | 4.0 / 0.5 / 3.7 / 4.8 |
| dayend | **289.1** | 250.0 | 8.5 | **24.4** | 292 086 | 0.3 / 0.3 / 0.0 / 4.9 |
| free | **289.1** | 250.0 | 8.5 | 24.4 | 292 086 | 0.3 / 0.3 / 0.0 / 4.9 |

### 秋季样本（47 天）

| 策略 | 总费用/万元 | 计划 | 偏差 | 紧急 | 弃电/kWh | 窗口紧急 0-6/6-12/12-18/18-24（万元） |
|---|---|---|---|---|---|---|

## 4. 结论

1. **段末硬目标是纯损失**：夏季样本 +40.3 万（12.2%）、秋季样本 +8.4 万（4.3%），
   全部来自中间段末的紧急购电尖峰（0-6 / 12-18 窗口几乎清零）；计划层与弃电差异不构成
   反向补偿。
2. **`dayend` 与 `free` 完全同值**：样本内日末目标不发生 binding；取更简洁、更易表述的
   `free` 作为统一口径。
3. **储能仍全幅利用**：两种样本下 SOC 区间均为 [1200, 10800]，无"排空/顶格卡死"迹象。
4. 计划层（2 日滚动、末端自由）不受影响；仅执行层去掉了人为目标。

## 5. 落地

- `consistency.EXEC_POLICY = "free"`（唯一参数源）；
- `q3_proto` 的 `simulate_day_rt_hedge / simulate_day_rt` 默认 `exec_policy="free"`；
- Q2 官方（`q2_tune.simulate_two_day`）、Q2 对照（`q2.run_deterministic`）、
  Q4 两层与蒙特卡洛执行全部改为无段末目标；
- 受影响正式结果（result2/3/4-2/4-3）将在统一重算时一并更新（另行执行）。
